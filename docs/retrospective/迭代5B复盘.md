# 迭代 5B 复盘：MCP 全面服务化与共享 PostGIS 数据面

## 一、迭代目标

把原先“本地文件随运行传递、本地 mock/stdio MCP、服务端返回本机文件路径”的同机模式，重构为：

```text
网络 MCP (SSE/HTTP)
+ 共享 PostGIS 库内断言
+ 受控 Opaque Data Handle
+ Run 隔离结果
+ 结果断言、归档、清理闭环
```

正式评测不再依赖本机临时文件搬运、`GEO_MCP_DATASETS` 环境变量注入及物理数据库表名的直接暴露。

---

## 二、实际完成内容（平台侧）

### 1. 协议设计与冻结

编写并建立了活文档 [`docs/design/04-MCP服务化数据协议.md`](../design/04-MCP服务化数据协议.md)：
- **控制面与数据面分离**：定义独立 HTTPS 控制面（`POST /admin/runs`、`POST /archive`、`DELETE /release`），不与 MCP `tools/list` / `tools/call` 混淆。
- **Opaque Handle 规范**：定义 `DatasetDescriptor` 结构，严禁在 handle 或元数据中携带 `table`、`path`、`schema`、`db_url` 等物理信息。
- **角色与权限划分**：明确 `input`、`result`、`reference` 角色边界，`reference` 仅对评测私有，禁止向 Agent 泄露。

### 2. 数据服务客户端与模型落地

- 新增 `geoskillbench.data_service` 模块（`DataServiceClient`、`DatasetDescriptor`、`RunRegistration`、`ArchiveResult`、`ReleaseResult` 等）。
- 实现了运行生命周期注册、数据 handle 绑定、归档调用以及幂等的 release 释放逻辑。

### 3. MCP Adapter 改造与安全脱敏

- **网络 Transport 硬切**：MCP Server 配置仅允许 `sse` 和 `http`，`mock` / `stdio` 配置在校验期直接抛出 ValidationError 拦截。
- **结果不透明化处理**：工具执行返回的物理数据集路径、URL 或表名由 Adapter 自动拦截并转换为 `dh_{run_id}_{alias}` 格式的安全 Handle，剥离真实位置信息。
- **结果注册与隔离**：Adapter 仅保留内部位置映射供断言比对使用，对外/对 Agent 暴露的信息无任何物理细节。

### 4. PostGIS 库内断言比较器

- 新增 `PostgisResultComparator`，直接在 PostGIS 数据库内通过 SQL 计算 `overlap_ratio`（重叠率）、`area_error`（面积误差）、`feature_count`（要素数量）等空间指标。
- `AssertionEngine` 优先使用库内比较器执行评测，无需将大体量 GIS 结果下载到本地。

### 5. 评测主流程闭环与清理机制

- `TestRunner` 串联生命周期：
  1. `PREPARE_DATA`：向数据服务注册 run，获取输入与 reference 的 handle；
  2. `CONNECT_MCP` / `RUN_AGENT`：Agent 仅感知并操作 opaque handle；
  3. `RUN_ASSERTIONS`：通过受控路径执行库内/内存断言；
  4. `CLEANUP`：触发 fixture 清理与数据服务 `release_run` 释放临时数据。

### 6. 测试基线与场景规范

- 新增 `tests/test_5b_data_service.py` 与 `tests/test_5b_protocol.py`，覆盖协议校验、transport 拦截、handle 脱敏、防跨 run 注入等。
- 全量 pytest（26 个测试）全部通过。
- 提供了 5B 规范样例场景：`scenarios/buffer_school_500m_5b_001.yml`。
