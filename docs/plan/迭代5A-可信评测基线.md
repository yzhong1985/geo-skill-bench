# 迭代 5A 计划：可信评测基线

> 状态：**已完成（2026-08-28）**。
>
> 定位：从原“迭代 5”大计划中拆出的前置小迭代。在 MCP/DB 数据面迁移前，先修正会造成明显误判的评测语义，并建立最小回归测试基线。

---

## 1. 要解决的问题

原评测链路存在“失败被包装成通过”的风险：

- Agent 报错、未完成或返回空内容，后续断言/Judge 仍可能让顶层结果通过；
- 空 assertions 会返回满分并视为通过；
- LLM Judge 不可用时会隐式降级为规则 Judge，可能形成正式通过；
- 连续运行 Scenario 时存在 Runner/Adapter 状态串扰风险；
- 没有最小自动化测试保护这些高风险语义。

## 2. 目标

```text
失败不能被判为通过。
```

具体目标：

1. Agent 执行失败、未完成或空响应不能得到正式通过；
2. 空断言必须是 `skipped`，不能伪造满分；
3. LLM Judge 意外不可用不能变成正式规则通过；
4. 显式选择的 `rule-based-*` Judge 仍然可以正常工作；
5. 每个 CLI 批量 Scenario 使用独立 Runner；
6. 增加可离线执行的最小回归测试。

## 3. 范围

### 纳入

- `RUN_AGENT` 完成、错误和空响应语义；
- Assertion 空列表语义；
- Judge disabled、显式规则 Judge 和 LLM 不可用语义；
- 最小结果状态字段与失败记录；
- 正常/异常路径的 Executor session 关闭尝试；
- CLI 目录运行的 Runner 隔离；
- pytest 测试依赖、关键单元测试和 Scenario 配置校验。

### 不纳入

- `reports/runs/<run_id>` 产物迁移、原子归档和失败 receipt；
- 全链路 secret 脱敏或完整路径安全治理；
- Task/SSE 重构、持久化、取消、队列和 retention；
- 完整 timeout / 线程生命周期治理；
- MCP 服务化、共享 PostGIS、handle 协议；
- repeat/batch/聚合统计、多轮 Judge 分析；
- CI/CD 修改、数据库 schema 迁移。

## 4. 关键规则

### 4.1 执行门槛

```text
Agent 报错 / 未完成 / 空响应
→ RUN_AGENT = FAILED
→ 正式评测结论不得 passed
```

### 4.2 空断言

```text
assertions = []
→ AssertionResult.status = skipped
→ score = 0.0
→ 不构成自动通过依据
```

### 4.3 Judge

```text
显式 rule-based-* 
→ 规则 Judge 可给出正式结果

LLM Judge 未配置、不可用或调用异常
→ judge_status = unavailable
→ 不自动降级为规则通过
→ 单次结果不得被其提升为 passed
```

### 4.4 状态分层

结果至少分别记录：

- `operational_status`：平台/执行是否成功；
- `evaluation_verdict`：Agent 是否通过评测；
- `status`：兼容性顶层状态；
- `failures`：结构化失败原因。

## 5. 完成内容

- 在 Runner 中加入执行成功门槛和集中 verdict 计算；
- 空 assertions 改为 `skipped`；
- 移除 LLM Judge 异常时的隐式规则通过；
- 增加 `FailureRecord`、运行/评测状态兼容字段；
- CLI 批量执行改为每个 Scenario 新建 `TestRunner`；
- 正常与异常路径尝试关闭 Executor session，adapter close 时清理内部注册状态；
- 添加 pytest 可选依赖和 18 个最小回归测试；
- 使用递归脱敏和路径 containment 的基础测试覆盖。
