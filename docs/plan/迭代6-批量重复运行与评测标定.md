---

## 1. 目标

解决当前平台“只能跑单次运行、无法量化随机性与稳定性”的痛点：
1. **支持单场景重复运行（Repeat）**：指定重复次数 $N$，评估 Agent 在相同任务下的通过率（Pass Rate）与过程稳定性；
2. **支持多场景批量运行（Batch）**：批量下发多个场景任务，汇总评测指标；
3. **量化方差与科学性标定（Calibration）**：
   - 耗时分布（均值、标准差、Min/Max）；
   - 工具调用一致性（工具总数方差、各工具使用频次分布）；
   - 交互轮次分布；
   - Judge 评分标准差与一致性；
4. **统一产物与 API 控制面**：
   - 批次产物独立保存于 `reports/batches/<batch_id>/`（`summary.json`、`summary.md`）；
   - 提供 `/api/batches` REST 与 SSE 实时事件流接口。

---

## 2. 步骤拆解

- **第 1 步**：数据模型与聚合统计核心（Batch Models & Statistics Aggregator）
- **第 2 步**：批次调度引擎与 Run 产物关联（Batch Runner & Artifact Persistence）
- **第 3 步**：API 控制面、SSE 实时事件与 DB 持久化（API, SSE & DB Integration）
- **第 4 步**：评测科学性标定与端到端回归（Harness Variance & Judge Calibration Baseline）

---

## 3. 边界与明确不做的事

1. 不做分布式 Celery/RabbitMQ 队列，依托进程内 TaskManager 调度；
2. 不做 Agent Prompt 自动微调；
3. 不放大前端地图渲染，聚焦数据统计与科学标定。
