# 迭代 6.1 计划：多维度 AI 批次诊断与标定引擎

> 状态：**已完成（2026-09-02）**。复盘接在 [../retrospective/迭代6复盘.md](../retrospective/迭代6复盘.md) 附录，不另开文件。活设计见 [../design/05-批次AI诊断.md](../design/05-批次AI诊断.md)。
>
> 定位：基于迭代 6（批量重复运行与方差统计基座），构建横向 AI 诊断与归因分析能力。解决“连续重复运行 N 次后，缺乏全局 AI 归因诊断、漂移定位与 Skill Prompt 修复建议”的问题。

---

## 1. 目标与范围

### 1.1 核心目标

1. **横向 AI 归因诊断 (Cross-Run Root-Cause Analyst)**：
   - 调 LLM 对 Batch 中 N 次重复运行的结果进行全局横向分析。
   - 自动生成**根因归因树与占比**（如：Skill 约束不足 40%、Agent 随机漂移 40%、环境抖动 20%）。
2. **Skill Prompt 建议补丁 (Skill Suggested Patch & Copy Only)**：
   - 当归因定位为 Skill 缺陷时，AI 诊断引擎直接输出标准的 Diff 格式 Prompt 修复建议。
   - 前端支持**查看与一键复制 Patch**（取消自动写回/修改本地 Skill 文件的操作，确保绝对安全）。
3. **前端轻量集成 (Progressive UI Component)**：
   - 实现组件化的批次 AI 诊断视图（`BatchAnalystView`），采用“上层核心简报 + AI 补丁，下层 Tab 展开明细”的渐进式设计。
   - 组件解耦，便于后续页面全局重构与导航迁移。

### 1.2 非目标 (Explicit Out of Scope)

- **取消一键写入本地 Skill 文件**（仅保留复制 Diff，防误修改源文件）。
- **暂不做 GIS 专属拓扑诊断**（如几何有效性、拓扑穿孔等，保留在后续企划）。
- **非重点：单次 Run 诊断**（保持现状轻量诊断，不作为本迭代重点）。
- **不做全站顶部导航页面的大型重构**（采用局部轻量组件嵌入，避免范围膨胀）。

## 2. 架构与 API 设计

### 2.1 数据模型扩展

在 `geoskillbench.models.batch` 中扩展诊断数据结构：

```python
class SkillPatchSuggestion(BaseModel):
    skill_id: str
    target_file: str
    diff_content: str  # diff 格式文本
    explanation: str

class BatchAIDiagnostics(BaseModel):
    batch_id: str
    created_at: str
    summary_text: str  # AI 宏观现象总结
    attribution_breakdown: dict[str, float]  # {"skill_prompt_issue": 0.5, "agent_drift": 0.3, "env_error": 0.2}
    root_cause_analysis: str  # 根因深度剖析
    suggested_patch: SkillPatchSuggestion | None = None
```

### 2.2 API 端点

- `POST /api/batches/{batch_id}/analyze`
  - 触发 LLM 对指定批次生成横向 AI 诊断报告，结果持久化至 `reports/batches/<batch_id>/ai_diagnostics.json`。
- `GET /api/batches/{batch_id}/diagnostics`
  - 获取批次的 AI 诊断结果。

## 3. 执行步骤

1. **第 1 步：后端 Batch AI Analyst 诊断引擎 (geoskillbench/runtime/batch_analyst.py)**
   - 设计横向分析 Prompt，输入完整的 BatchSummary 及各子 Run 的轨迹与断言。
   - 实现分类归因算法与 Skill Diff 建议生成。
2. **第 2 步：API 控制面与持久化扩展**
   - 增加 `/api/batches/{batch_id}/analyze` 与 `/api/batches/{batch_id}/diagnostics` 端点。
   - 产物落地 `reports/batches/<batch_id>/ai_diagnostics.json`。
3. **第 3 步：前端轻量级组件与交互 (`BatchAnalystView.jsx`)**
   - 实现卡片简报、AI 总结、Git Diff 组件以及 **[复制 Patch]** 按钮。
   - 嵌入现有控制台。
4. **第 4 步：标定测试与端到端回归**
   - 编写 `tests/test_batch_analyst.py`，验证归因解析与 Patch 生成逻辑。
